# 前端显示名称

1. **目标**是让用户打开页面时，从名称看出这是面向数仓的查数工具。
2. **讲透命名**。「数仓」说明数据来源，「查数」说明使用场景。作品介绍可用「基于数据字典和字段血缘生成可审核的 SQL」，补充查数依据和产出。
3. **选型**采用「数仓查数助手」。如果技术作品集希望直接突出 SQL，可以用「数仓 SQL 助手」。
4. **可迁移的做法**是把前端显示名当作报表标题，把内部项目名当作调度作业标识。面向用户改名时，按可见入口核对文案。
5. **代码**同步更新页头 `web/src/App.tsx`、登录页 `web/src/state/auth.tsx`、浏览器标题 `web/index.html` 和 `web/package.json` 的描述。
6. **常见坑**是只改页头，漏掉登录页和标签页。打包后的三处名称 3/3 一致。前端类型检查及构建通过，项目全量回归 2043/2043 通过。

## 旧浏览器认证弹窗

正式域名首页仍由 Nginx 的 Basic Auth 拦截，所以浏览器先显示系统认证弹窗。应用登录已启用，应用侧匿名访问元数据、会话、管理、接口文档和健康接口均返回 401。计划只关闭正式域名的外层认证。自动审批要求用户就这一线上访问变更明确授权，现场配置尚未更改。

用户确认后仅关闭正式域名的外层认证，保留应用账号登录和内网入口的 Basic Auth。配置校验及重载通过，后端原进程持续运行。全新浏览器会话直达「数仓查数助手」登录页。实际登录返回 200，退出返回 204，退出后访问元数据返回 401 并可回到登录页。内网入口仍返回 Basic Auth 认证请求。服务端备份位于 `/opt/agentflow/deployments/public-login-20261120T030757Z`。
